# Ручной приоритет и режимы дома

## Presence Device Control

В `presence-device-control.yaml` можно выбрать необязательный `pause_timers`:
таймер Home Assistant с включённым восстановлением состояния (`restore: true`).

- Команда включения или выключения управляемого устройства от пользователя
  Home Assistant запускает таймер ручного приоритета (по умолчанию 30 минут).
- Таймер можно запустить отдельно, например кнопками на 30 или 60 минут.
- Пока таймер активен, приостановлен или недоступен, автоматизация не посылает
  команды устройству. По возврату таймера в `idle` она сверяет присутствие и
  возобновляет управление. Отмена таймера возвращает автоматику досрочно.
- Физический выключатель без `user_id` в контексте не считается подтверждённой
  пользовательской командой: для него ручной приоритет включается отдельной
  кнопкой таймера. Это предотвращает ложную паузу при восстановлении связи.
- Если таймер не выбран, сохраняется прежнее поведение blueprint.

## Режимы дома

Создайте помощник `input_select` с вариантами `Дома`, `Ушли`, `Сон` и
автоматизацию по `home-mode-control.yaml`. Выберите свет и музыкальные
плееры, которыми она должна управлять.

| Режим | Действие |
|---|---|
| Дома | Обычная автоматика; устройства принудительно не включаются |
| Ушли | Выключить выбранный свет; приостановить играющую музыку |
| Сон | Приостановить играющую музыку |

Для ночной подсветки выберите этот же помощник в необязательном входе
`home_mode_entities` blueprint `night-lighting-occupancy.yaml`:
`Сон` разрешает ночной свет по присутствию вне расписания, а `Ушли`
подавляет автоматические команды подсветке. Имена этих двух режимов
можно изменить во входах blueprint. Без помощника работает прежнее расписание.
Вход `turn_off_main_in_ambilight` позволяет сохранить выбранное поведение
основного света в обычном режиме; в режиме сна основной свет выключается
при включении Ambilight независимо от этого флага.

Переключение режимов само по себе не управляет отоплением, замками или уборкой.
Привязка к геолокации добавляется отдельной автоматизацией после проверки
надёжности определения присутствия.

## Проверки

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-test.txt
.venv/bin/python -m unittest discover -s tests -v
```

Проверки читают условия из самих blueprint: приоритет ручных команд,
возврат после таймера, совместимость без новых входов и действия режимов.
