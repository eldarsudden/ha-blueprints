# Температурная поправка Opening limit

База задаётся в поле **Базовый Opening limit** blueprint
(`sensor_opening_percentage`, по умолчанию 15%). Значение на устройстве
не используется для базы или расчёта ступеней. В number-сущность
Opening limit отправляется только рассчитанный результат.

| Температура O-Air / у окна | Доля базы | При базе 15% | При базе 20% |
|---|---:|---:|---:|
| от 15 °C | 100% | 15% | 20% |
| от 10 до 15 °C | 75% | 11% | 15% |
| от 0 до 10 °C | 50% | 8% | 10% |
| ниже 0 °C | 25% | 4% | 5% |

Результат округляется до целого процента, минимум — 1%. Температурные
границы настраиваются отдельно и должны идти по убыванию. Для
увеличения открытия по умолчанию нужны запас 1 °C относительно границы
и две минуты непрерывного потепления. Уменьшение применяется сразу.

Чтобы включить поправку в конкретной автоматизации, выберите отдельный
датчик O-Air в разделе температуры у окна и number-сущность Opening limit.
Комнатный датчик остаётся отдельным входом: он ограничивает проветривание
по температуре комнаты. Датчики у окна исключаются из автоматического
поиска комнатной температуры. O-Air — приближённый ориентир, его показания
могут зависеть от состояния окна и тепла комнаты.

Поправка обновляет только окна, открытые текущим запуском автоматизации.
При изменении лимита команда открытия повторяется для этих окон, чтобы
привод применил новый предел. Открытые вручную окна не перенастраиваются.
Закрытие по температуре комнаты продолжает действовать для них, как раньше.

Без выбранного датчика у окна сохраняется фиксированный лимит. При
недоступных показаниях выбранного датчика действует осторожная ступень
25% базы. Если для поправки не выбрана number-сущность или границы
температур заданы неверно, новое автоматическое открытие блокируется;
сопровождение уже открытых окон и закрытие по холоду остаются доступны.

Ключ `sensor_opening_percentage` сохранён для совместимости: явные значения
из существующих автоматизаций остаются их базой после обновления blueprint.
